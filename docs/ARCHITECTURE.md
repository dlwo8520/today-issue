# 기술 구조

문서 점검일: **2026-10-16 KST**

현재 서비스는 **저장된 뉴스 JSON을 읽는 화면**과 **이메일 입장을 처리하는 서버**로 동작합니다. 뉴스 수집과 GPT 요약 구현은 소스에 남아 있으며, 공통 정책으로 실행을 차단합니다.

## 현재 방문 흐름

~~~mermaid
flowchart LR
  A[브라우저] --> B[Pages Worker<br/>이메일·쿠키 확인]
  B --> C[화면 파일·고정 뉴스 JSON]
  A --> D[첫 원문의 사진 URL]
~~~

화면은 React·TypeScript·Vite·Tailwind CSS로 구성했습니다. 상세 페이지는 `#/issue/이슈ID` 형태의 hash 경로를 사용합니다.

입장 서버는 `server/email-gate.mjs`입니다. 별도 회원 DB 없이 이메일을 비교하고 서명 쿠키를 확인한 뒤 정적 파일을 전달합니다. GPT·뉴스 API 키는 이 서버에 필요하지 않습니다.

## 파일과 역할

| 위치 | 역할 |
|---|---|
| `src/App.tsx` | 데이터 로드, 로딩·오류 상태, hash 경로 |
| `src/pages/` | 홈과 상세 화면 |
| `src/types/news.ts` | Zod를 이용한 브라우저 입력 검증 |
| `pipeline/models.py` | Python 데이터 계약 |
| `config/service.json` | 프로젝트 갱신 정책 |
| `pipeline/service.py` | 수집·모델 호출 차단 |
| `server/email-gate.mjs` | 이메일 비교와 쿠키 서명 |
| `scripts/build_private.py` | 입장·보호 설정 확인 후 기존 실제 데이터 빌드 |
| `scripts/build_public.py` | 선택한 공개 가능 데이터만 별도 빌드 |

## DEMO와 실제 뉴스

| 모드 | 데이터 | 의미 |
|---|---|---|
| `demo` | `public/data/demo.json` | 가상 사건·가상 매체로 구성한 체험 화면 |
| `live` | `public/data/latest.json` | 실제 뉴스 데이터 형식; 현재는 10월 15일 고정본 |

모드는 `VITE_DATA_MODE`로 선택합니다. `live`라는 이름이 실시간 수집을 뜻하지는 않습니다. 실제 파일이 없거나 잘못되면 오류를 표시하고 가상 기사로 대체하지 않습니다.

## 데이터의 시각과 근거

| 필드 | 의미 |
|---|---|
| `windowStart`·`windowEnd` | 기사 선정에 사용한 기간 |
| `collectionStartedAt` | 기존 뉴스 수집 시작 시각 |
| `updatedAt` | 기존 에디션 생성 완료 시각 |
| Source의 `publishedAt` | 원문 기사 발행 시각 |

같은 사건의 보도는 출처와 함께 보관합니다. 제목·요약·문장에 연결된 출처 ID, 사실·주장 구분, 주장 주체, 용어 설명도 데이터 계약에 포함됩니다.

문장별 출처 번호는 화면에서 제거했지만 내부 근거 참조와 상세의 원문 링크는 유지합니다. 사진은 첫 번째 원문의 이미지 URL을 읽고, 이미지 로드가 실패하면 해당 영역을 숨깁니다.

## 갱신 차단

현재 `config/service.json`의 `updates_enabled`는 `false`입니다.

1. Live CLI가 실행되면 파일을 쓰거나 클라이언트를 만들기 전에 종료합니다.
2. API/RSS 실행 함수를 직접 호출해도 정책을 확인합니다.
3. 뉴스 어댑터와 GPT 요약기의 직접 호출도 차단합니다.
4. 정책 파일이 없거나 잘못되어도 호출을 허용하지 않습니다.

화면에는 `고정 에디션`과 `고정 기준 시각`을 표시합니다. 의도적으로 고정한 상태이므로 30시간 경과 경고를 띄우지 않고 `status.json`도 조회하지 않습니다.

## 중지 전 생성 구조

중지 전에는 다음 순서로 에디션을 생성했습니다.

수집 → 정규화·중복 정리 → 같은 사건 묶기 → 복수 출처 조건 확인 → 최신 발행 순 선정 → GPT 근거 추출·요약·검토 → 코드 검증 → JSON 저장

마지막 에디션의 범위는 336시간, 검증 통과 결과는 6개입니다. 조회수·댓글수는 이 순서의 우선순위로 사용하지 않습니다.

생성 단계의 상세 구현과 당시 호출 상한은 [API 파이프라인 구현 이력](API_LIVE_INTEGRATION.md)에 보존했습니다. 현재 배포 동작은 [배포와 운영](DEPLOYMENT.md), 검증 범위는 [검증 안내](VALIDATION.md)를 기준으로 확인합니다.
