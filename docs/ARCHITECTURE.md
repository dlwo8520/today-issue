# 기술 설계와 결정

## 2026-10-13 API 추가 설계

현재 기본 Live 수집은 GNews 주요 후보 발견과 NewsData 관련 보강입니다. 기존 RSS는 `--collector rss`로 유지합니다. API의 공통 필드·중복 공급자 병합·선정 가중치·구간 ID 인용·요청 상한·캐시·비공개 공개 차단은 [API 설계 문서](API_LIVE_INTEGRATION.md)에 정리했습니다.

현재 API 선택 전략은 `latest`이고 Edition은 호환 표기 `coverage_recency`, `publicationScope=local_private`와 Source의 `providers/publisherKey/imageUrl`을 지원합니다. 기간과 그룹화는 336시간이며 첫 원문 사진 URL과 PC 상세 이동 목록을 추가했습니다. 전체 현재 구조는 [1차 정리](PHASE_1_REPORT.md)에 있습니다. API SDK 재시도는 0회이며 GPT 결과마다 토큰과 요율을 기록합니다. 아래의 RSS 수집 수치·기존 가중치·재시도 설명은 초기 RSS 경로의 기준입니다. 현재 실제 검사 결과는 [VALIDATION](VALIDATION.md)을 확인하세요.

## 1. 실행 경계
React는 공개 JSON만 읽는다. Python에서 수집·텍스트 분석·OpenAI 호출·검증을 마친 후 배포한다. DB, 상시 서버, 사용자 계정이 없으므로 발행 비용과 운영 부담이 작다. OpenAI 키는 Python 환경변수 또는 GitHub Secret이며 Vite 변수로 전달하지 않는다.

## 2. 데이터 계약
`pipeline/models.py`가 Python의 계약이며 `data/edition.schema.json`은 여기서 생성한다. 프론트는 같은 필드를 `src/types/news.ts`의 Zod로 검사한다. ISO-8601 timezone offset, `Asia/Seoul`, 스키마 버전 1을 사용한다. `windowStart/windowEnd`는 선정 범위, `collectionStartedAt`는 수집 시작, `updatedAt`는 게시 준비 완료 시각이다. Article의 `collected_at`은 실제 파싱 시각이다.

각 Issue는 제목/요약의 출처 ID, 문장 배열, 각 문장의 fact/claim 구분·주체·출처 ID, 관련 Source, Ranking을 포함한다. 출처 URL은 HTTP(S)이고 인증 정보가 없어야 한다. 출처 존재·문장 ID 유일성·이슈 ID 유일성·연속 순위는 Python에서 검증하며 프론트도 주요 참조와 순위를 검사한다.

`null`은 미관측이며 실제 0과 다르다. Article의 Engagement에는 조회수/댓글수/순위, 순위의 모집단 크기, 관측 시각, 관측 출처를 기록한다. RSS에서는 이 값이 기본적으로 null이다. API 확장 시 숫자를 제공하려면 출처와 관측 시각이 필수이다.

## 3. 수집
`NewsSourceAdapter.collect()` 인터페이스와 `RSSAdapter`를 사용한다. 허가 정보가 없는데 enabled=true이면 설정 검증에서 거부한다. 수집은 timeout 15초·재시도 최대 2회·크기 2MiB·매체별 최대 120항목으로 제한된다. HTTP 4xx는 즉시 실패하여 접근 제한을 우회하지 않는다. 5xx/연결 오류만 지수 간격 재시도한다.

RSS 제목·허가된 excerpt·URL·발행일만 읽는다. 사진과 전체 기사 HTML을 가져오지 않는다. 발행일 없이 updated 시각만 있는 항목은 임의 대체하지 않는다. timezone이 없는 발행일은 소스별 시간대가 명시된 경우에만 해석한다. 잘못된 항목·지난 24시간 밖의 기사·미래 발행 기사를 제외한다. 실패한 한 소스 때문에 성공한 다른 소스의 데이터를 버리지 않는다.

정규 URL은 fragment와 알려진 추적 파라미터를 제거하고 기사 식별 query는 보존한다. 동일 URL이면 더 충분한 excerpt를 가진 항목을 사용한다. 정규 URL의 SHA-256 앞 16자리로 출처 ID를 만들며 장문 URL 자체를 ID로 사용하지 않는다.

## 4. 사건 그룹화
제목에서 기관 별칭·동결/유지 표현을 정규화하고 머리말 및 구두점을 정리한다. 2·3·4글자 n-gram 빈도에 `tf=1+log(count)`, `idf=1+log((1+N)/(1+df))`를 곱하고 단위 벡터로 정규화한다. 벡터 내적으로 코사인 유사도를 계산한다. 기본 임계치는 .40이다.

그룹 안 모든 기사와 유사도·사건 조건이 맞아야 들어갈 수 있다. 다음은 병합을 차단한다.

- 발행 시각 차이가 20시간을 초과
- 제목에 명시된 날짜가 다름
- 알려진 핵심 기관이 서로 다름
- 인상/인하, 동결/인하, 승인/거부 등 반대 행동

complete-link는 넓은 제목 하나가 두 사건을 이어 붙이는 오류를 줄이지만, 조사·새로운 인물·날짜 표현을 모두 해석하는 방법은 아니다. 알려진 기관과 별칭 목록은 설정 가능하다. 기본 상한은 8개 소스×120항목이며 최악에는 대략 O(N²) 비교를 수행한다. 대규모 기사량을 목표로 한 구현이 아니다.

## 5. 관심도와 이슈 점수
관측된 views/comments에 log1p를 적용하고 동일 언론사 내 관측 집합에서 동률 평균순위 백분위를 계산한다. 2개 미만이거나 전부 같은 값인 집합은 비교 신호가 없어 null을 유지한다. 관측 순위와 총 순위 수가 있으면 `1-(rank-1)/(total-1)`을 사용한다. 한 기사에 여러 지표가 있으면 평균하고, 사건 안 같은 매체는 최대값 하나만 반영한다. 서로 다른 언론사의 원시 조회수는 비교하지 않는다.

| 요소 | 식 | 기본 가중치 |
|---|---|---:|
| engagement | 매체별 정규화값의 평균, 없으면 null | .35 |
| diversity | min(서로 다른 언론사 수/6, 1) | .25 |
| independence | min(알려진 원출처 수/6, 1) | .20 |
| recency | exp(-최신 기사 경과 시간/12시간) | .15 |
| sufficiency | min(excerpt 50자 이상인 원출처 수/3, 1) | .05 |

최종 점수 = `Σ(관측 요소×가중치) / Σ(관측 요소 가중치)`이다. engagement가 null이면 분모에서 제외한다. 기사 개수 자체를 더하지 않기 때문에 동일 매체의 반복 보도는 다양성 점수를 높이지 않는다.

알려진 통신사 이름이 명시되면 원출처 key를 `wire:yna/newsis/news1`로 낮춰 통합한다. 연합뉴스 자체도 wire:yna로 설정한다. 이것은 명시적 전재만 처리하며 숨은 전재·공통 보도자료까지 완전히 탐지하지 않는다. 최소 독립 출처 2개를 요구한다. API 계약이 없으므로 인기 순위를 연결하지 않았으며 현재 RSS 선정은 coverage_recency이다. 사용자 반응을 직접 측정했다고 주장하지 않는다.

상위 후보 12개까지 검토해 검증된 최대 6개를 순서대로 발행한다. 부적격 후보가 있으면 다음 후보를 시도한다. 6개 미만은 그대로 표시하고, 0개이면 이전 정상 에디션을 보존한다.

## 6. GPT 및 검증
이슈마다 원출처별 대표 기사를 먼저 선택하고 최대 8개로 제한한다. 제목과 excerpt, 발행일, publisher, independenceKey를 JSON 데이터로 전달한다. 소스 URL을 모델에 읽게 하거나 임의로 링크를 따라가게 하지 않는다.

① **추출:** fact/claim, 주체, 원자료에 정확히 등장하는 quote, 출처 ID, 상충 finding ID. 인용 문자열이 원문에 없으면 즉시 실패한다.

② **요약:** title·oneLineSummary·background/currentSituation/response 문장·terminology. 반응이나 배경을 원자료로 확인할 수 없으면 빈 배열이다. 용어 역시 제공된 자료로 설명할 근거가 있어야 한다.

③ **검토:** 별도 Responses 호출이 제목, 요약, 모든 문장, 모든 용어를 검사한다. 검토 ID의 집합은 요약 세그먼트의 집합과 정확히 같아야 한다. supported, 출처, 이유, conflictsHandled를 검사한다.

④ **결정적 검사:** 출처와 검토 범위, 발화 주체, 정확한 인용, 입력에 없는 숫자, 본문에 없는 용어, 중복 ID, 필수 필드, URL 형식. 실패는 게시 후보에서 제외한다.

LLM의 의미 검토가 잘못 통과할 수 있으며 단순 숫자 검사는 숫자의 문맥까지 확인하지 않는다. 동일 모델의 추가 호출은 독립적인 진실 확인 기관이 아니다. 기사에 적힌 내용이 실제 사실이라는 보장도 없다. 실제 운영 전 사람의 편집 검토와 실제 뉴스 평가가 필요하다.

## 7. 장애와 발행
출처 장애는 격리하고 공개 경고에는 실패 개수만 기록한다. LLM 후보 장애는 제외한다. 전체 결과가 없으면 `latest.json`을 건드리지 않고 실패 상태를 저장한다. 정상 JSON은 스키마 검사 후 같은 폴더의 임시 파일에 쓰고 fsync 및 os.replace로 교체한다. 동시 로컬 실행은 O_EXCL 잠금으로 차단한다.

정상 본문과 상태 파일은 서로 별도 원자적 쓰기이다. 두 파일 전체의 단일 트랜잭션은 아니다. 프론트는 실패 attemptedAt가 본문 updatedAt 이상인 경우에만 해당 실패를 현재 것으로 표시한다. update가 30시간 이상 오래되면 별도 상태를 못 읽어도 지연 안내를 표시한다.

Actions는 동시 실행을 직렬화하고 이전 news-state artifact를 검증하여 복원한다. 복원 가능한 이전 JSON이 없는데 이번 발행도 실패하면 새 artifact 배포를 중단한다. 운영 인프라를 실제로 실행해 확인한 것은 아직 아니다.

## 8. 브라우저
정적 상대 base 경로와 hash 라우팅을 조합한다. 새로고침은 항상 index.html을 가져오고 해시에서 이슈를 찾아 별도 서버 rewrite 없이 상세 페이지를 표시한다. 직접 공유는 현재 에디션에서 지원한다. 과거 에디션 보존은 이번 MVP 범위에 포함하지 않았다.

브라우저에서 OpenAI를 호출하거나 기사 수집을 수행하지 않는다. 원격 폰트를 사용하지 않는다. 초기 DEMO에는 사진이 없었으며 현재 Live는 첫 원문 사진 URL을 lazy loading으로 표시한다. 검증 번들이 포함되어 초기 JS는 약 101KiB gzip이며 실제 전송 속도나 Lighthouse 성능 점수는 측정하지 않았다.
